# Architecture

Vertiku is a Node.js 24 application with a Fastify HTTP boundary, React client, SQLite persistence through the Drizzle node-sqlite adapter, and local FFmpeg/ffprobe adapter processes. The server owns every upload, working-result, and published-output path; browser input never becomes a command or filesystem path. Read-only `/input` sources are referenced in place. Default results are encoded and validated as hidden partial files on the `/output` filesystem, then published without byte copying through an exclusive hard link. Browser-download results remain in private `/data` storage.

The application uses an in-process FIFO scheduler backed by SQLite. All conversion parameters, source references, and the current five-step worker phase persist before or during execution; interrupted running jobs are returned to `queued` at startup, and phase/progress changes are streamed with server-sent events. Concurrency is an invariant fixed at one: a batch can contain up to 100 books, but source analysis, encoding, and validation happen serially. Queue estimates use source duration or a clearly labelled byte-based early estimate and learn a processing-to-audio-duration ratio from the account's completed jobs. The API exposes the running job estimate separately from the aggregate of that job and every queued job. A failed retryable attempt remains immutable in history; a retry creates a new linked job and reuses retained sources. A later worker split can keep the same claim-and-adapter contract without changing the browser contract, while preserving that invariant unless a future AppSpec explicitly changes it.

Trust boundaries are the browser/session boundary, multipart upload parser, read-only `/input` mount, persistent media directories, SQLite database, and FFmpeg process. Account ID is included in every draft, job, media stream, and artifact lookup. Mounted folder identifiers are canonicalized below the configured root, and directory traversal does not follow symlinks. Preflight fingerprints use filename, byte size, and modification time without reading full media bytes; they detect stale submissions but are not presented as cryptographic content identity.

## Code layout

`src/server/app.ts` only registers plugins, builds the shared services, and wires the route modules. HTTP endpoints live in `src/server/routes/` (`system`, `auth`, `drafts`, `jobs`). `sessions.ts` and `security.ts` own sessions, cookies, CSRF, and secret comparison; `conversion-runner.ts` executes the serial queue and owns the FFmpeg child processes; `job-views.ts` builds the job and queue-forecast representation; `event-stream.ts` serves server-sent events with keep-alive comments and closes them on shutdown; `upload-retention.ts` bounds private upload storage. Pure audiobook rules (natural order, chapter titles, FFmetadata, safe filenames) stay in `src/domain/`.

The React client keeps only the application shell in `src/client/main.tsx`. Views live in `src/client/components/`, while `api.ts`, `format.ts`, `job-status.ts`, `job-order.ts`, and `appearance.ts` hold transport, formatting, status text, overview grouping, and theme handling.

## Private upload retention

Uploaded sources are private copies below `/data/uploads/<draft-id>`. Successful and cancelled jobs remove them immediately; failed jobs keep them so a retry needs no new upload. A retention sweep at startup and every six hours removes, after `VERTIKU_UPLOAD_RETENTION_DAYS` (default 7), drafts that never became a job, upload copies whose jobs are all finished and that no visible failed attempt can retry, and upload directories without a draft. It acts only on server-generated directory names, never follows symlinks, and never touches job history, forecast samples, browser-download results, `/input`, or `/output` (STOR-001, DEC-0002).
